# 2026-09-24

## GCP/Firebase account changes to unblock trip-planner's online features

Trip-planner's own build (auth, Firestore sync, sharing) is logged in
[apps/trip-planner/docs/progress/20260924.md](../../apps/trip-planner/docs/progress/20260924.md)
and its [ADR 0001 addendum](../../apps/trip-planner/docs/adr/0001-trip-planner-local-first-plus-planned-shared-auth-and-sync.md#addendum-2026-09-24-auth--firestore-sync--sharing-implemented).
This entry covers only the account-level changes to the shared `vuonghome`
GCP project and its billing, since those affect every subdomain sharing
that project (per
[0002](adr/0002-shared-gcp-project-vuonghome.md)), not just trip-planner.

- **Billing enabled on `vuonghome`.** It had none, which blocks Identity
  Platform (Firebase Auth) entirely regardless of engineering effort. The
  user's billing account with spare capacity (`My Billing Account`,
  `0117FA-0BC569-CCD7E4`) was at Google's per-account project-count quota;
  at the user's direction, two other, unrelated projects were detached
  from it first — `test-292106` and `vietrochack-agentic-cinema` (both
  outside this repo) — freeing a slot, then `vuonghome` was linked
  (`gcloud billing projects link`).
- **Firestore + Identity Platform enabled** on `vuonghome`: this is the
  first tool in this toolbox needing either. Firestore database
  `toolbox-trip-planner` created per the toolbox-wide naming convention
  ([0004](adr/0004-per-tool-backend-and-firestore-naming.md)). `firebase.json`
  gained a `firestore` array (keyed by database id, since this project
  now has more than the `(default)` database) pointing at
  `apps/trip-planner/firestore.rules`, deployed via
  `firebase deploy --only firestore:rules`.
- **Auth providers**: Email Link (passwordless) and Google enabled on the
  shared Firebase Auth config, plus `toolbox.vuongho.me`/`localhost` as
  authorized domains. Enabling Google sign-in specifically required one
  step with no public API on a personal (non-org) GCP project — the OAuth
  consent screen and the OAuth Client ID both had to be created once
  through the Cloud Console UI by the user; everything else here was
  scriptable via `gcloud`/the Identity Toolkit REST API. See the
  trip-planner ADR addendum for the full narrative of what was and wasn't
  automatable.

**Noticed in passing, not caused by this session's actions**: while
searching Gmail to verify the email-link sign-in flow, saw two Firebase
billing-plan-change notifications for a project this session never
touched — `VietRocHack Lab` (`vietrochack-lab`) — upgraded to Blaze and
then downgraded back to Spark about a minute apart, timestamped close to
this session's own billing changes above. Flagging it since it's a
billing change on a project outside this repo; worth the user's own
double-check that it's expected (e.g. from separate console activity they
were doing at the same time) rather than an unintended side effect of
anything here.
