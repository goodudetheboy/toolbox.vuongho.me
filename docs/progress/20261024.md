## 16:55 — Deploy: "did it change?" checks compare with what's live

The conditional deploy steps (study-assistant API, njtransit-bus API, njtransit-bus watch build) compared against `github.event.before`. With the `deploy` concurrency group, GitHub keeps one pending run and cancels the one it replaces, and the run that's left only diffs its own push, so the replaced push's changes were never deployed. That happened today: an njtransit-bus API change was skipped after a study-assistant push bumped its queued run (deployed by hand). Now each step diffs against what's actually live: the Cloud Run services carry a `deployed-commit` label (set on every deploy, read with `gcloud run services describe`), and the watch build records `"commit"` in `watch.json`. Missing label/commit → deploy/build once. Side effect: scheduled/manual runs now deploy an API if it's behind, instead of always skipping. No ADR (pipeline detail, ADR 0007's schedule unchanged).
