## Reworked docs/ into per-app ADRs, progress logs, and CLAUDE.md files

User asked to split up the docs setup: each app should own its own
`CLAUDE.md`, `docs/adr/`, and `docs/progress/` for content specific to that
tool, while the root `docs/` keeps only toolbox-wide decisions and light
cross-tool metadata. Wrote up the decision and the split itself as
[ADR 0005](../adr/0005-per-app-docs-and-claude-md.md) — see it for the full
before/after mapping of every ADR and progress file. Summary:

- Former root ADRs 0004/0005/0007–0011 (all pdf-redactor's own decisions)
  moved to `apps/pdf-redactor/docs/adr/`, renumbered 0001–0007. Former 0012
  moved to `apps/audio-transcriber/docs/adr/0001`. Former 0013 moved to
  `apps/trip-planner/docs/adr/0001`. Former 0006 (the per-tool backend/
  Firestore naming convention) stayed at root as 0004, since it's a
  toolbox-wide convention, not one tool's own decision.
- Root ADRs 0001–0003 (monorepo structure, shared GCP project, hosting
  routing) stayed at root unchanged — genuinely toolbox-wide.
- Each day's progress log was split the same way: toolbox-wide events
  (scaffolding, GCP deploys, CI/CD setup, a tool being wired into the
  homepage/launch config, cross-tool lessons that landed in the root
  `CLAUDE.md`) stayed at root; each tool's own build/bug-fix/decision
  narrative moved to that tool's own `docs/progress/`. Every root day-file
  now points to that day's per-app file(s) where relevant, and vice versa.
- Every app got a new `CLAUDE.md` (dev command, architecture notes specific
  to that tool, pointer to its own `docs/adr`/`docs/progress`). Root
  `CLAUDE.md` was trimmed to stay repo-wide only and now points to each
  app's own `CLAUDE.md` instead of absorbing app-specific detail.
- Cross-references between an app-level ADR/progress file and a root-level
  one are called out explicitly as "toolbox-wide" in the link text, so it's
  always clear when a reference crosses that boundary.

Went ahead with pushing this directly to `main` too, alongside the
trip-planner work above, per the same "ship it so I can test" instruction —
this change is docs-only (nothing in `apps/*/dist` changes), so the
production deploy this triggers is a no-op for the live site itself.
