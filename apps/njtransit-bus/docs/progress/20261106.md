# 2026-11-06

## Alerts sheet: pull past the end to go back to the board

At the user's request: pulling on past the end of the service alerts sheet
closes it (the same slide as the close button), like snapping between the
board's countdown and its list. Touch: an 80 px pull that starts with the
sheet already at its end; wheel/trackpad: 160 px in one gesture that starts
there, so a scroll or fling that only reaches the end doesn't close it. A
visible "BUSES" strip to snap onto was tried first; the user didn't want it.
Typechecked and built; not tried in a browser yet (user to check on the phone).

## Pull down at the board's top to open the alerts

The other way round, at the user's request: pulling down past the top of the
board opens the alerts sheet (same slide as tapping the red banner), only
when the board has alerts. Both pulls now share `src/lib/pull.ts`
(`usePullPast`), same rules: the pull must start at the edge, 80 px by touch,
160 px by wheel. The scroller's `overscroll-behavior: contain` keeps phone
pull-to-refresh out of it; a pull doesn't count toward the double-tap flip.
Built; not tried in a browser.

## Took the board's pull-down back out

The user wants pulling down at the board's top kept for loading (refresh), so
it no longer opens the alerts; the red banner does. `usePullPast` stays, used
by the alerts sheet's pull-to-close.
