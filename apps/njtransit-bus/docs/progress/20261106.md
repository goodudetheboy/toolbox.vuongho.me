# 2026-11-06

## Alerts sheet: pull past the end to go back to the board

At the user's request: pulling on past the end of the service alerts sheet
closes it (the same slide as the close button), like snapping between the
board's countdown and its list. Touch: an 80 px pull that starts with the
sheet already at its end; wheel/trackpad: 160 px in one gesture that starts
there, so a scroll or fling that only reaches the end doesn't close it. A
visible "BUSES" strip to snap onto was tried first; the user didn't want it.
Typechecked and built; not tried in a browser yet (user to check on the phone).

## Pull down at the board's top to open the alerts

The other way round, at the user's request: pulling down past the top of the
board opens the alerts sheet (same slide as tapping the red banner), only
when the board has alerts. Both pulls now share `src/lib/pull.ts`
(`usePullPast`), same rules: the pull must start at the edge, 80 px by touch,
160 px by wheel. The scroller's `overscroll-behavior: contain` keeps phone
pull-to-refresh out of it; a pull doesn't count toward the double-tap flip.
Built; not tried in a browser.

## Took the board's pull-down back out

The user wants pulling down at the board's top kept for loading (refresh), so
it no longer opens the alerts; the red banner does. `usePullPast` stays, used
by the alerts sheet's pull-to-close.

## Alerts as a page of the board's scroll

The user didn't like the alerts sheet sliding/snapping as an overlay; wanted
it to move like scrolling from the countdown to the list. Raised the conflict
with keeping the board's top pull for loading; the user picked: the alerts page
only exists while open. Now tapping the banner adds a red page above the
countdown in the board's own scroller (view kept in place), then scrolls up to
it; scrolling down snaps to the countdown under the finger like the list does,
and once the scroll rests at the countdown or below, the page is removed with
the view kept in place (`overflow-anchor: none` on the scroller so the browser
doesn't shift it too). The X scrolls down to the countdown; a flip removes it
at once. The overlay's slide animations and `usePullPast` are gone. ADR 0005
amended.

Built and typechecked only: Playwright/Chromium isn't set up in this container
any more, so not tried in a browser. To check on the phone: open from the
banner, scroll down through long alerts, close with X, and that pulling down
at the top no longer opens anything.

## Fix: opening alerts scrolled up from the bottom of the list

The user found that tapping the banner scrolled all the way up from the end of
the bus list instead of from the countdown. Chrome keeps a snapped element in
view when content above it changes, so when the alerts page appeared the view
had already moved down by the page's height, and the code shifted it by that
much again. Board.tsx now sets positions outright: the countdown's position
plus where the board was when opened (and on removal, how far past the
countdown the view was), so it's right whether the browser adjusts or not.
Built; not tried in a browser.
