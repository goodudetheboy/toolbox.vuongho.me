# 2026-09-27

## 14:00 — Trip notes

**What changed**: trips now have an optional free-text `notes` field
(`Trip.notes?: string` in `types.ts`). It's edited in the trip form (a
textarea under the dates, on both "New trip" and "Edit trip / notes" — the
button was renamed from "Edit trip / dates") and shown plainly under the
trip's title/dates in the itinerary view (`.trip-notes`, `white-space:
pre-wrap` so line breaks survive). Hidden when empty.

Plumbed through `useTrips.createTrip`/`updateTripDetails`,
`cloud.goOnline`/`subscribeTrip`/`updateCloudTripDetails`, and the import
validator (`notes` must be a string if present; older exports without it
still import). Optional in the type so pre-existing local trips and cloud
docs load fine without a migration.

`firestore.rules`: added `notes` to the keys a non-owner editor may
change. Owners could already update any field.

**Verified**: `tsc --noEmit`, and created a local trip with multi-line
notes in the dev server; they rendered under the title as expected. Cloud
path not exercised live.

**Decisions**: none needing an ADR — additive field on the existing model.

**Open TODOs**: `firestore.rules` change needs deploying
(`firebase deploy --only firestore:rules --project vuonghome`) before
non-owner editors can save notes on shared trips.

## 20:05 — Shipped notes; Google Maps places on activities

Notes (above) shipped straight to `main` per user instruction, and the
`firestore.rules` change was deployed — that TODO is closed.

**Places**: the activity form has a "Place" search box (Google Places
autocomplete, `src/components/PlacePicker.tsx` + `src/lib/places.ts`).
Picking a suggestion attaches `Activity.place` (name, address, lat/lng,
Maps URL) and fills the title if it's empty; "Remove" detaches it. The
activity card shows "📍 name · address" linking to Google Maps. Optional
field, so older activities/exports are unaffected; the import validator
checks its shape when present. Firestore: stored as a nested map on the
activity doc (rules already allow any activity fields for editors);
omitted rather than `undefined` since Firestore rejects undefined.

Infra: enabled `places.googleapis.com` on `vuonghome` and created a
dedicated referrer- and API-restricted browser key — see
[ADR 0002](../adr/0002-google-places-for-activity-locations.md).

**Verified**: `tsc` + `vite build`; in the dev server searched "ichiran
shibuya", picked a result, saved — card rendered with the place and a
working Maps link. Confirmed with curl that the key is rejected from a
foreign referrer. Cloud (Firestore) path not exercised live.

**Open**: no quota cap set on the Places API (see ADR consequences).
