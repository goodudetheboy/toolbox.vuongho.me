# 2026-09-25

## 21:30 — Recording playback per segment + Lucide icons

What changed:
- Each transcript row has a play button that seeks the original recording
  to the segment's start and plays it. Clicking the playing row's button
  again pauses. The row under the playhead is highlighted. The play button
  also shows in edit mode. A native `<audio controls>` bar sits under the
  transcript header (`src/components/RecordingPlayer.tsx`).
- The recording comes from `src/lib/useRecording.ts`. It uses, in order:
  the queued `File` in this session, a `File` reopened from a saved File
  System Access handle, or a file the user attaches by hand. See
  [ADR 0002](../adr/0002-recording-playback-via-file-handles.md). IndexedDB
  goes to version 2 with a new `mediaHandles` store. Only handles are
  stored, never media bytes.
- Picking and dropping files go through `src/lib/filePicker.ts`:
  `showOpenFilePicker` / `getAsFileSystemHandle` when available, otherwise
  `<input type=file>`. The hidden inputs are gone from `DropZone`.
- All emoji icons are replaced with `lucide-react` (new dependency), in the
  header, dropzone, queue, history, transcript actions, and split/merge.
  The `←` back arrow, `×` close buttons and `▾` are replaced too.

Verified in dev (browser pane, `localhost:5174/audio-transcriber/`):
- The v1 → v2 IndexedDB upgrade creates `mediaHandles`.
- A history transcript seeded with an OPFS file handle loads on reload with
  no click (permission already granted). Clicking row 3's play button
  seeks to 6s and plays, highlights row 3, and changes the button to Pause.
  Clicking again pauses.
- A history transcript with no handle shows "Attach file…". Attaching (with
  a stubbed picker returning a handle) loads the player and saves the
  handle.
- Deleting the backing file and reloading shows the "moved, renamed, or
  deleted" error with Attach. Deleting a history item also removes its
  handle.

Not verified here:
- The "Reopen" permission-prompt state. OPFS handles are always granted, so
  a handle to a real disk file is needed in a real Chrome session.
- The Firefox/Safari fallback path (no handles).
- Queue path (in-session): dropped a WAV and faked the worker's
  CHUNK_DONE/DONE messages through a temporary dev-only hook (removed
  afterwards). The player loaded the queued file, and the row-2 play button
  seeked to 4s and highlighted row 2.

Decisions: [ADR 0002](../adr/0002-recording-playback-via-file-handles.md).
