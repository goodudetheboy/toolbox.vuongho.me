# 2026-10-13

## 17:30 — Parakeet as an opt-in model

The user asked whether eg2.haku.sh ("Embedding Gemma Transcribe", 1h of
audio in 13s) could speed this tool up. It can't be reused: it's a
Mac-only app running on the Apple Neural Engine. Its reader and
punctuation models aren't published, and it's English-only at ~5% WER.
Parakeet came up as the practical alternative, and the user asked to try
it.

What changed (see [ADR 0004](../adr/0004-parakeet-model-option.md)):
- New "Parakeet (experimental)" model option (`parakeet-tdt-0.6b-v2` via
  `parakeet.js` 1.4.4). Whisper base stays the default.
- `src/workers/parakeet.worker.ts` uses the same decoder protocol and
  returns timed words per window. `src/lib/transcriber.ts` picks the
  windowing and merge per model. Parakeet merges by word-midpoint
  ownership plus sentence grouping. Whisper's path is unchanged.
- Parakeet runs one worker with `min(hardwareConcurrency, 8)` ORT threads.
  WebGPU (fp16 encoder) is only tried when `shader-f16` exists; otherwise
  it uses WASM int8.
- Retry/resume only reuses finished windows for the same model.
- `vite.config.ts`: `worker.format: 'es'`. The production build failed
  without it, because parakeet.js code-splits. `worker.type` wasn't a real
  option.

Benchmarks: headless Chromium, 4 cores, WASM only (no real GPU). The
harness was temporary and isn't committed.
- 8.7 min LibriSpeech (73 dev-clean utterances concatenated):
  Whisper base 5.8× / 10.1% WER. Parakeet 6.2× / 3.5% with parakeet.js's
  own long-audio stitching, 5.5× / 3.4% through our pipeline.
- 29.3 min earnings call (earnings21 `4394084`, 6 speakers):
  - Whisper base: 6.2× / 25.5% WER.
  - Parakeet with parakeet.js `transcribeLongAudio` auto (90s) windows:
    5.9× / 40.4%. It dropped long stretches.
  - Parakeet via `transcribeLongAudio`, 30s windows: 6.3× / 21.5%.
  - Our pipeline, 60s windows: 6.1× / 30.4%.
  - Our pipeline, 30s windows: 5.6× / **20.4%**.
- Conclusion: same speed on CPU, clearly more accurate. The encoder is
  ~96% of Parakeet's time, so the speed win depends on WebGPU, which
  couldn't be measured here.

Verified on the production build (`firebase-tools serve`): Parakeet
selected in Settings, a 45s clip transcribed end to end with sentence
segments and timestamps. Whisper is still fine after the worker-format
change. WebGPU selected without `shader-f16` falls back to WASM cleanly.
