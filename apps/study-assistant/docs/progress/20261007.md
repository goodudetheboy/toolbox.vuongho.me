## 02:35 — Exams and cram sheets

Shipped the design worked out with the user today, with mockups on a Design canvas. See the ADR 0001 addendum "exams and cram sheets".
- An exam is a name, a date and notes or picked parts.
- Home has "My notes | Exams" tabs.
- New/Edit exam has a note search and a per-part picker.
- A note's ⋯ menu has "Add to exam".
- The cram sheet shows ~5 min at a time with "give meow more", two sorts (Most relevant / Most important), and local "I remember this" ticks. Its ⋯ menu has Edit / Delete exam.

Backend: `/tag` endpoint (Gemini idea split + importance 1–3, `sanitizeTags`). Tags are stored at `notes/{id}/parts/{n}`, made in the background on note create and part save, and re-made by the sheet when stale. `firestore.rules`: own `exams`. Tokens now carry `bold`, so excerpts keep the note's highlighted key phrases.

Tests: api 7/7, web 14/14 (new `cram.test.ts` plus a bold-token test); tsc and build pass. Clicked through the whole flow on the mock build in headless Chromium at 390 px: tabs, form search, part picker, sheet, ticks, give-more → "That's everything", ⋯ menus, the Add to exam dialog. No console errors. Fixed from the screenshots: the sort toggle wrapped onto two lines, and bold words were highlighted one by one. This container needed Chromium's system libraries and fonts unpacked from Debian packages into the scratchpad (no root).

## 03:05 — Cram sheet: long legacy notes

The user asked whether a very long old note works. It mostly did, but there were two real bugs:
- A part Gemini skipped in a big batch was saved as one filler idea, permanently.
- One part over 2,000 words made `/tag` reject its whole batch, so every part in it got the fallback on every open.

Fixes: `/tag` returns `null` for skipped parts, and those aren't saved. Oversized parts aren't sent and just use the fallback. Batches are now 20 parts, 3 in parallel, and a failed batch no longer throws away the others. Checked on the mock build: a 150-part note with one 2,200-word part opened its sheet in about 2.5 s, with 149 parts tagged and saved and the big part on the fallback. Tests 16/16 + api 7/7, tsc pass.
