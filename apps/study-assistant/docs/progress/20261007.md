## 00:30 — Admin page: Feedback + Usage tabs

`/admin` now has tabs: Feedback (the old page, now `screens/AdminFeedback.tsx`) and Usage (`/admin/usage`, lazy `screens/AdminUsage.tsx` + `lib/usage.ts`). The Home link reads "Admin".
Usage shows sessions in the last 7 and 30 days, active days, the 30-day average score, and a bar chart of sessions per day for the last 30 days (tap or hover a bar to see its count). It also has a People table (last seen, app opens, notes, parts, sessions, average score) and the top 5 most practiced parts, plus a chip to filter by person.
Data: collection-group reads of `notes` and `attempts` (admin-only rules), plus a new `users/{uid}` profile (email, name, lastSeenAt, opens) that the app writes on each load. Until someone opens the app after this deploy, their row shows "–" for last seen and opens, and their name is a short uid. ADR 0001 addendum updated.
tsc, tests and build pass. Not run in a browser and the rules weren't emulated: there's no Chromium or Java in this container.
Open: check /admin/usage loads after deploy. If it shows the error state, a collection-group rule is the likely cause. API/Gemini call counts would need the API to log usage into Firestore.
