## 21:55 — Screen transitions

Screens slide when the route changes, using the View Transitions API (`router.ts`). Opening a screen slides the new one in from the right, going back slides it in from the left, and a replace (e.g. a new note opening its own page) just fades. Only `.screen` (`view-transition-name: screen`) animates, so the graph-paper desk stays put. Back vs forward on popstate comes from an `idx` stored in `history.state`. Skipped when the browser already animated a swipe-back (`hasUAVisualTransition`, iOS Safari), with reduced motion, and in browsers without `startViewTransition` (they just switch instantly like before). tsc, tests and build pass. There's no browser in this container, so the mock build went to preview channel `page-transitions` (expires 2026-10-07).
