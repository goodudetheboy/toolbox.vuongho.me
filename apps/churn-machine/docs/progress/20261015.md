# 2026-10-15

## 13:50 — First version

Built from scratch at the user's request: browse Doctor of Credit's bank bonuses in a friendlier way, plan which accounts to open with a biweekly paycheck, and track accounts once signed in.

What changed:
- Deal data: `scripts/refresh-deals.mjs` and `parse-deals.mjs` read the index plus 247 unique posts through DoC's WordPress REST API in 8 requests (robots.txt asks for a 600 s crawl delay, so scraping 265 pages daily was out). Parsing is regex-only. Before and after each fix I audited coverage across all deals and spot-checked them by hand. Real misreads I found and fixed, each now a test: bonus amounts read as DD requirements (Chase "bonus of $300"); per-month and per-deposit DD not multiplied out (Navy Federal, PSECU); footnote digits as transaction counts; "closed within 12 months" read as a 360-day payout; state lists left in bank names; a stale glance "DD: No" (Suffolk); a balance tier list (BMO); stale end dates superseded by "deal is back" notes. Coverage on today's data: 151 DD deals (amount for most, window for ~60%), 83 balance requirements, 77 transaction counts, 119 payout times, 95 future end dates, 86 with none listed, 48 past their listed date but still listed by DoC (flagged, not hidden), 18 ended.
- Headline vs. post: when the index amount isn't in the post (HSBC "$7,000", M&T, Simmons, Chime portal…), the list still shows the headline, but value and plans use the post's own bonus, with a note. Without this, HSBC ranked first at a misleading $4.5k net.
- App: Deals / Plan / My accounts with History-API paths. The planner does greedy picks validated by full re-simulation (ADR 0002). All 12 strategies take ~20–40 ms.
- Accounts: Firestore `toolbox-churn-machine`, owner-only rules (ADR 0003). `VITE_FIREBASE_EMULATORS=1` dev switch for local testing.

Verified: 14 parser tests + 7 planner tests pass; tsc and build pass. Ran the account functions end to end against the Firestore/Auth emulators (save plan → walk an account planned→closed → track a deal → delete plan; another user and signed-out visitors are denied). Clicked through the whole UI in headless Chromium at 1100 px and 390 px, including emulated Google sign-in → "Use this plan" → "I opened it" → "I opened this". No console errors besides the missing favicon. Fixed from screenshots: truncated requirement lines and a cramped header and plan stats on mobile, and "rest ($0) → main" noise.

Decisions: ADRs 0001–0003 here, plus the toolbox-wide 0007 (daily deploy).

Open / known limits:
- Tiered offers are planned at their top tier only; "DD **or** X" alternatives are treated as no DD.
- ~20 deals have no DD/balance/transaction requirement found. Many really are that easy (eStatements, promo code), but some have spend requirements the parser doesn't model (Percapita's $300/month spend). The planner labels them "check the post".
- No dedupe if the same plan is saved twice.

## 14:10 — Installable as an app

At the user's request, Churn Machine can now be installed (PWA). It uses the same setup as study-assistant: the manifest is scoped to `/churn-machine/`, the shell is precached, `deals.json` is network-first so it works offline, and a new version waits for an "Update" tap. There's a new coin-stack icon, Plan and My accounts shortcuts, a popup-then-redirect Google sign-in, and safe-area padding when installed. Hosting now sends `no-cache` on `/churn-machine/**` (replacing the `deals.json` max-age rule). See ADR 0004.

Verified on the production build in headless Chromium: no installability errors with a real profile (only `in-incognito` in a throwaway one), and offline a `/plan` deep link renders the strategies from cached deals. One bug found and fixed that way: a `urlPattern` function referencing `BASE` never matched inside `sw.js`. Not checked: the actual install prompt and home-screen icon on a real iPhone or Android. That needs a phone.

## 16:40 — Terminal look, deal modal, "Banks I have"

At the user's request:
- **Bloomberg Terminal look:** black background, amber command bar and labels, white data, green/red numbers, function-key tabs, square edges. IBM Plex Mono is bundled (the real Bloomberg font is proprietary) and precached for offline use. The app is dark only now, and the PWA theme colour is black.
- **Deals open in a modal**, not an accordion. The list is now a dense table. The modal has a "Full page" button that goes to `/churn-machine/deal/<id>`, a two-column page that also shows DoC's at-a-glance lines. Back returns to the list.
- **Plan:** clicking a bank (by account or by paycheck) opens the same modal.
- **Banks I have:** a dropdown picker (scroll or type) that hides those banks on Deals and makes the planner skip them. It's on the Deals chips row and in the Plan panel, and both use the same list.

Decision: ADR 0005.

Verified on the production build (`firebase serve`) in headless Chromium at 1200 px and 390 px: picker adds/removes banks and the list and plans drop them; row → modal → Esc; modal → Full page → Back; a deep link to an unknown id shows the "not on the list" message; plan bank links and paycheck split links open the modal. No console errors. 14 parser tests and 7 planner tests pass, and tsc passes.

Open: the excluded-banks list lives in localStorage, so it isn't synced to the account. Android's back button doesn't close the modal; it leaves the page instead.

## 19:20 — Redesign: Robinhood style, purple on white

The user hated the terminal look ("so ugly") and asked for Robinhood's style in purple on white. This replaces the look but keeps the modal, the full page and "Banks I have". See ADR 0006, which supersedes the look in ADR 0005.

What changed:
- New tokens and type (Inter, `#6f2cf3`), with the stylesheet rewritten from scratch. The app icon, theme colour and manifest are now purple/white, and the icon PNGs were regenerated from `icon.svg`.
- Deals: big title, a pill search box, chips, a scrolling "Top picks" card row, and rows with purple price pills. On desktop, filters and "Banks I have" sit in a right sidebar. On phones they open as a bottom sheet from a "Filters" chip, with a "Show N deals" button.
- Deal: a stock-page layout (hero bonus, net in purple, "Key statistics" grid, "Is it worth it?" as order-summary rows, hairline Details). The full page has a sticky "Open at <bank>" card on the right. On phones the modal is a bottom sheet with the track button pinned to its foot, and the full page gets a sticky action bar above the tab bar.
- Plan: inputs in a right "Build your plan" card. Strategy rows have a sparkline and a net pill. An opened strategy shows a cumulative-payout step chart whose hero number follows the crosshair (pointer or arrow keys).
- Accounts: a big "Bonuses earned" number with a stats row.
- Phone: bottom tab bar with icons. Desktop: sticky blurred top bar with pill nav.

Verified on the production build in headless Chromium at 1280 px and 390 px: picker → list and plans drop those banks; row → modal → Esc; modal → full page → back; plan bank and paycheck links open the modal; the chart hover updates the readout; the filter sheet opens and closes. No console errors. Tests and tsc pass.

Not verified: the signed-in Accounts list and the account detail with real data. The Firestore emulator needs Java, which this machine doesn't have, so I only saw the signed-out state of that screen.
